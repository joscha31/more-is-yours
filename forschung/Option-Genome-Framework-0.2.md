# MORE IS YOURS – OPTION GENOME FRAMEWORK 0.2

**Stand:** 15.09.2026  
**Status:** FACH-LAB-VORSCHLAG / Arbeitsgrundlage, nicht automatisch PETRA APPROVED  
**Zuständig:** Option Genome Lab  
**Geltungsbereich:** fachliche Content-Library, nicht technische Implementierung

## Zweck

Das Option Genome beschreibt die **reale wirtschaftliche Außenwelt** von More is Yours.

Es beantwortet nicht: „Ist diese Option gut oder schlecht?“

Sondern:

> **Was verlangt dieser wirtschaftliche Weg tatsächlich, wie entsteht Geld, wie sieht der Alltag aus und was verändert sich, wenn er funktioniert?**

Grundlage ist der Gesamt-Master 3.0. Claude Code darf Option-Genome-Inhalte nicht selbst erfinden.

---

# 1. Grundregeln

1. Optionen werden neutral beschrieben – weder romantisiert noch abgewertet.
2. Varianten werden nicht glattgebügelt.
3. Zahlen brauchen Quelle, Datum, Region und Status.
4. Wenn eine belastbare Zahl nicht existiert oder zu stark vom Untertyp abhängt, lautet der Eintrag ausdrücklich `unbekannt` oder `nicht sinnvoll auf Familienebene quantifizierbar`.
5. Schätzungen werden als Schätzung markiert.
6. Matching erzeugt später eine Hypothese, keine automatische Entscheidung.
7. Der normale Dienstag wird nur aus belegten Optionsdaten erzeugt – keine erfundenen Uhrzeiten, Kundenszenen oder Tagesgeschichten.
8. Wachstum wird separat betrachtet: Start → stabil → Wachstum → größere/neue Rolle.
9. Harte persönliche Grenzen werden nicht durch Pluspunkte der Option kompensiert.
10. Fehlendes Wissen über eine Option führt zu Recherche im Option Genome – nicht zu einem Test der Frau.

# 2. Evidence Header pro Option

Jede Option erhält mindestens:

- **Option-ID**
- **Name**
- **Optionsfamilie**
- **Variante / Untertyp**
- **Region**
- **Prüfdatum**
- **Version**
- **Status**
- **Quellen**
- **Vertrauensgrad**
- **offene Annahmen**
- **nicht verallgemeinern**

## Vertrauensgrad

Empfohlene Arbeitslogik:

- **hoch** – Primärquelle / Gesetz / zuständige Behörde / mehrere konsistente belastbare Quellen
- **mittel** – belastbare Sekundärquelle oder gute Marktdaten, aber nicht universell
- **niedrig** – kleine Stichprobe, Anbieterquelle, Erfahrungswert oder starke Kontextabhängigkeit
- **offen** – noch nicht ausreichend recherchiert

# 4. Pflichtmodule pro Option

## A. Normaler Dienstag

Kernfrage:

> **Willst du den Alltag, der dieses Einkommen produziert?**

Darzustellen sind – soweit für die Option belegt oder als variabel markiert:

- Kundenkontakt
- Akquise
- Sichtbarkeit
- Verkauf
- Content
- Administration
- Termine
- Team
- Leistungserbringung / Lieferung
- Recherche / Vorbereitung
- Leerlauf / Warten
- Ortsbindung

Status:

- **Teilansicht möglich** – mindestens ein belegter Baustein
- **Dienstag ausreichend beschrieben** – zentrale Arbeitsrealitäten sind belegt oder ausdrücklich nicht relevant

Keine willkürliche Mindestzahl.

## B. Wachstumsrealität

Kernfrage:

> **Willst du auch die erfolgreiche spätere Version dieses Geschäfts?**

Vier Entwicklungsstufen:

1. Start
2. stabil
3. Wachstum
4. größer / neue Rolle

Zu prüfen:

- voller Kalender / Kapazitätsgrenze
- Spezialisierung
- Preisentwicklung
- Team
- Führung
- Kapital
- Plattformrisiko
- Produktisierung / Standardisierung
- neue Zeitbindung
- Rollenwechsel

## C. Reality Layer

Pflichtfragen:

- Was wird an dieser Option romantisiert?
- Was unterschätzen Einsteigerinnen?
- Welche typischen Engpässe oder Scheitergründe gibt es?
- Welche Aussagen sind stark vom Untertyp abhängig?
- Welche sinnvollen kleinen Realitätschecks gibt es?
- Welche Annahme soll mit jedem Realitätscheck geklärt werden?

# 5. Fach-Lab-Vorschlag: Optionsfamilie ≠ konkrete Tätigkeit

**Status: FACH-LAB-VORSCHLAG – vor technischer Änderung Petra Review erforderlich.**

Der Belastungstest mit `Teilzeit-/Nebenjob` zeigt:

Eine wirtschaftliche Optionsfamilie kann die **Geld- und Vertragsmechanik** beschreiben, ohne den tatsächlichen Arbeitsalltag vollständig festzulegen.

Beispiele:

- Teilzeit im Verkauf
- Teilzeit in der Buchhaltung
- Teilzeit im Kundensupport

haben dieselbe grobe Einkommensmechanik „Arbeitsentgelt vom Arbeitgeber“, aber völlig unterschiedliche Tätigkeiten, Menschenkontakt, Sichtbarkeit, Ortsbindung und normalen Dienstag.

Dasselbe Problem tritt bei Freelancing auf:

- Copywriting
- virtuelle Assistenz
- Webdesign
- IT-Spezialisierung

teilen eine selbstständige Dienstleistungsmechanik, aber nicht denselben Alltag und Markt.

### vorgeschlagene Dreiteilung

1. **Optionsfamilie** – wirtschaftliche Mechanik
2. **Optionsvariante** – relevante strukturelle Ausprägung
3. **Rollen-/Tätigkeits-Overlay** – konkrete Arbeit, wenn sie für den Dienstag und das Matching nötig ist

Ziel: keine Scheingenauigkeit auf Familienebene und keine unnötige Explosion in hunderte Optionen.

# 6. Fach-Lab-Vorschlag: Begriffe für nicht-kundenzentrierte Optionen

**Status: FACH-LAB-VORSCHLAG.**

Das Masterfeld `Wofür zahlt der Kunde?` funktioniert bei Anstellung sprachlich nicht sauber. Arbeitgeber zahlen Arbeitsentgelt, nicht „Kunden“.

Arbeitsvorschlag für fachliche Beschreibung:

> **Wer zahlt – und wofür?**

Das technische Masterfeld kann bis zu einer freigegebenen Änderung bestehen bleiben.

Ebenso ist `Kundengewinnung` bei Anstellung unpassend. Fachlich kann ergänzend von

> **Zugang zum Einkommen**

gesprochen werden: Bewerbung, Netzwerk, Akquise, Plattform, Content, Empfehlungen, Partnerschaften usw.

Noch keine technische Umbenennung ohne Petra-Freigabe.

# 7. Zahlen- und Quellenregel

Jede quantitative Aussage erhält möglichst:

- Wert / Spanne
- Einheit
- Region
- Bezugsjahr
- Quelle
- Quellentyp
- Prüfdatum
- Einschränkung

Zulässige Statuswerte:

- **belegt**
- **belegte Spanne**
- **Schätzung**
- **stark kontextabhängig**
- **offen / unbekannt**

Keine Zahl wird allein deshalb zur „Wahrheit“, weil sie in einer Datenbank gespeichert wird.

# 8. Erste Goldstandard-Optionen

Gemäß Gesamt-Master 3.0:

1. Teilzeit-/Nebenjob
2. Freelancing / Done-for-you
3. Digitales Produkt

Erst diese drei vollständig fachlich recherchieren und als Belastungstest verwenden. Danach die restlichen sieben Startoptionen.

---

# 9. Definition of Done für eine Goldstandard-Option

Eine Option ist fachlich ausreichend für den ersten Pilot, wenn:

- die relevanten Kernfelder befüllt oder bewusst als unbekannt/variabel markiert sind,
- wesentliche Varianten sichtbar sind,
- jede relevante Zahl nachvollziehbar belegt ist,
- der normale Dienstag ohne erfundene Szenen erzeugt werden kann,
- die Wachstumsrealität beschrieben ist,
- Romantisierungen und Anfängerfallen benannt sind,
- mindestens 2–4 kleine Realitätschecks ableitbar sind,
- offene Wissenslücken ausdrücklich sichtbar bleiben,
- keine Scheingenauigkeit erzeugt wird.
