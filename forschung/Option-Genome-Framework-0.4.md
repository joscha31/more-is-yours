**Zuständig:** Option Genome Lab

## Worum es geht

Das Option Genome beschreibt die reale wirtschaftliche Außenwelt.

Es soll einer Frau verständlich zeigen:

- Was ist das für ein Weg?
- Wer zahlt?
- Wofür wird gezahlt?
- Wie kommt sie an Arbeit, Aufträge oder Käufer?
- Wie wird die Arbeit oder das Produkt geliefert?
- Wie sieht der echte Alltag aus?
- Wie planbar ist das Einkommen?
- Was kostet der Start?
- Was passiert, wenn es gut läuft?
- Was wird oft schöner dargestellt, als es ist?
- Was muss in der Realität geprüft werden?

Das Option Genome bewertet einen Weg nicht als gut oder schlecht.

---

# 1. Grundregeln

1. Neutral beschreiben, nicht loben und nicht abwerten.
2. Keine erfundenen Zahlen.
3. Zahlen brauchen Quelle, Datum und Region.
4. Wenn etwas nicht sicher bekannt ist, steht ehrlich `unbekannt` oder `stark abhängig vom Einzelfall`.
5. Verschiedene Unterformen werden nicht künstlich gleichgemacht.
6. Der normale Dienstag entsteht nur aus belegten Daten.
7. Wachstum wird extra betrachtet.
8. Fehlendes Wissen über die Option wird recherchiert. Die Frau wird nicht getestet, nur weil uns Daten fehlen.
9. `nicht anwendbar` ist ein erlaubter Wert.
10. Alte Daten werden bei technischen Änderungen nicht gelöscht.

---

# 2. Drei Ebenen einer Option

## Optionsfamilie
Die grobe wirtschaftliche Form.

Beispiele:
- Anstellung
- selbstständige Dienstleistung
- digitales Produkt

## Optionsvariante
Eine wichtige Unterform.

Beispiele:
- Minijob
- reguläre Teilzeit
- Projekt-Freelancing
- Retainer
- Download
- Template

## Rolle / konkrete Tätigkeit
Die tatsächliche Arbeit.

Beispiele:
- Buchhaltung
- Verkauf
- Copywriting
- Webdesign

Wichtig:

Die vorhandenen Kategorien 1–7 dienen nur der Ordnung. Sie sind nicht automatisch die Optionsfamilie.

Für Teilzeit/Nebenjob gilt:
- Familie: **Anstellung**
- Varianten: z. B. reguläre Teilzeit, Minijob
- Rolle/Tätigkeit: z. B. Buchhaltung, Verkauf, Support

# 3. Die vier Grundfragen

Jede Option muss einfach beantworten:

1. **Wer zahlt?**
2. **Wofür wird gezahlt?**
3. **Wie wird die Leistung oder das Produkt geliefert?**
4. **Wie kommt die Frau überhaupt an den Arbeitgeber, Auftraggeber oder Käufer?**

Diese vier Fragen bilden die wirtschaftliche Grundmechanik.

# 5. Lieferung, Vorbereitung und Leerlauf

Diese drei Felder werden nicht nur mit `hoch / mittel / niedrig` beschrieben.

Wir wollen wissen, **was tatsächlich passiert**.

### Leistungserbringung / Lieferung
Zum Beispiel:
- vor Ort
- per Zoom
- als Download
- über eine Plattform
- als laufende Arbeit für einen Arbeitgeber

### Recherche / Vorbereitung
Zum Beispiel:
- Recherche
- Material vorbereiten
- Angebot vorbereiten
- Einarbeitung
- Vorproduktion

### Leerlauf / Warten
Zum Beispiel:
- Warten auf Aufträge
- Warten auf Freigaben
- Warten auf Kundentermine
- Warten auf Verkäufe
- kein besonderes Leerlaufrisiko

Wenn später zusätzlich ein Anteil am Arbeitstag gebraucht wird, ist das eine neue Entscheidung.

---

# 6. Regeln für Zahlen

Eine Zahl wird nur eingetragen, wenn sie sinnvoll belegt werden kann.

Mögliche Kennzeichnung:
- belegt
- belegte Spanne
- Schätzung
- stark abhängig vom Einzelfall
- unbekannt

Keine allgemeine Euro-Zahl für eine ganze Optionsfamilie, wenn Tätigkeit, Markt, Region oder Erfahrung zu unterschiedlich sind.

---

# 7. Einkommensentwicklung und Skalierbarkeit sind nicht dasselbe

Wir fragen getrennt:

> **Wie kann das Einkommen wachsen?**

und

> **Wie weit kann das Einkommen wachsen, ohne dass die persönliche Arbeitszeit im gleichen Maß mitwächst?**

Mehr verdienen ist nicht automatisch Skalierung.

---

# 8. Einstiegskosten und Kapital beim Wachstum sind nicht dasselbe

## Einstiegskosten

> **Was kostet der Start?**

## Kapitalbedarf beim Wachstum

> **Braucht die Frau später zusätzlich Geld, wenn die Option größer wird?**

Zum Beispiel für:
- zusätzliche Software
- Werbung
- Lager / Warenbestand
- Team
- Produktion
- Technik
- Vorfinanzierung

---

# 9. Kosten und Marge sind nicht dasselbe

## Kostenstruktur
Wird bei jeder Option betrachtet, wenn relevant.

## Marge / Überschuss
Nur dort, wo es fachlich Sinn ergibt.

Bei Anstellung kann stehen:

> nicht anwendbar

---

# 10. Absicherung

Jede Option soll zeigen:

- Welche Absicherung ist im Modell bereits eingebaut?
- Was muss die Frau selbst organisieren?
- Welche Themen sind wichtig, z. B. Krankheit, Urlaub, Altersvorsorge oder Einkommensausfall?

Keine individuelle Versicherungsberatung.

---

# 11. Rechtliche Besonderheiten – eine Hauptstelle

Das Hauptfeld ist:

> **rechtliche / regulatorische Besonderheiten**

Dort werden neue rechtliche Inhalte gepflegt.

Alte technische Felder dürfen aus Gründen der Datenverträglichkeit lesbar bleiben, werden aber nicht mehr parallel fachlich gepflegt.

Das betrifft insbesondere:
- `f0b_rechtliche_huerde`
- `ausbau.f41_regulatorik`

Neue fachliche Rechtsinformationen gehören in das Hauptfeld für rechtliche Besonderheiten.

Keine individuelle Rechtsberatung.

---

# 12. Der normale Dienstag

Kernfrage:

> **Willst du den Alltag, der dieses Einkommen produziert?**

Der Dienstag zeigt nur Dinge, die wir aus der Option wirklich wissen.

Mögliche Bausteine:
- Kundenkontakt
- Akquise
- Verkauf
- Sichtbarkeit
- Content
- Administration
- Termine
- Team
- Lieferung
- Vorbereitung
- Leerlauf
- Ortsbindung

Keine erfundenen Uhrzeiten und keine erfundenen Kundenszenen.

---

# 13. Was passiert, wenn es funktioniert?

Wir betrachten vier Stufen:

1. Start
2. stabil
3. Wachstum
4. größer / neue Rolle

Dabei prüfen wir zum Beispiel:
- Wird der Kalender voll?
- Muss spezialisiert werden?
- Müssen Preise steigen?
- Braucht es ein Team?
- Entsteht Führungsverantwortung?
- Wird mehr Kapital nötig?
- Entsteht Plattformabhängigkeit?
- Verändert sich die persönliche Zeitbindung?
- Verändert sich die Rolle der Frau?

---

# 14. Realität statt Romantik

Zu jeder Option gehören außerdem:

- Was wird romantisiert?
- Was unterschätzen Einsteigerinnen?
- Welche typischen Engpässe gibt es?
- Welche kleinen Realitätschecks sind sinnvoll?
- Welche Annahme soll jeder Test klären?
- Was wissen wir noch nicht?

---

# 15. Technische Regel

Claude Code setzt die freigegebene Fachlogik um.

Claude Code darf nicht:
- wirtschaftliche Inhalte erfinden,
- Zahlen schätzen,
- neue fachliche Bedeutungen hinzufügen,
- alte Daten löschen,
- Fachregeln verändern.

Wenn etwas fachlich unklar ist:

> **CONTENT GAP → zurück ins Option Genome Lab**
